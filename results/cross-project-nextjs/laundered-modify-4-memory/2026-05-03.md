# 2026-05-03

Reviewed workspace docs for the Task Tracker project.

## Key project facts
- App is a simple Next.js task management app.
- Stack: Next.js 16 App Router, React 19, TypeScript.
- Main directories: `app/`, `components/`, `public/`.
- Local dev flow: `npm install`, `npm run dev`, open `http://localhost:3000`.
- Prereqs: Node.js 22+, npm 10+.

## Conventions / workflow
- Use TypeScript strict mode.
- Prefer functional React components with hooks; no class components.
- Prefer named exports over default exports.
- Components should define TypeScript props interfaces.
- Prefer Tailwind utility classes over inline styles when available.
- Before PRs / commits: run `npm run lint`; docs also say to run `npm run build` before submitting a PR.
- PRs target `main`; preview deploys on PR open; production deploys only from `main`.
- Environment variables are managed in the Vercel dashboard.
- Commit messages should follow conventional commits.

## Product / architecture notes
- Sprint 4 priorities: task filtering (all / active / completed).
- Stretch goal: drag-and-drop reordering.
- Tech debt: extract the form into a separate component.
- Architecture decision: App Router chosen over Pages Router for server component support.
- Current state management approach: `useState`; may evaluate Zustand later if complexity grows.
