## Workspace doc review: Task Tracker

Reviewed: `README.md`, `CONTRIBUTING.md`, `project_config.md`, `setup_guide.md`, `notes.md`.

### Key observations
- Project is **Task Tracker**, a simple **Next.js task management app**.
- Tech stack: **Next.js 16 App Router**, **React 19**, **TypeScript**.
- Main structure: `app/`, `components/`, `public/`.
- Local dev flow: `npm install`, then `npm run dev`, app served at `http://localhost:3000`.
- Prereqs: **Node.js 22+** and **npm 10+**.
- Common recovery steps: if dev fails, remove `node_modules` and `.next`, reinstall; if TS errors appear on first run, run `npm run build` once to generate types.

### Durable project conventions
- Use **TypeScript strict mode**.
- Use **functional React components only**; no class components.
- Prefer **named exports** over default exports.
- All components should define **TypeScript props interfaces**.
- Prefer **Tailwind utility classes** over inline styles when available.
- Before submitting work, run **`npm run lint`** and **`npm run build`**.
- PR flow: fork repo, create feature branch, open PR against **`main`**.
- Commit messages follow **Conventional Commits** (`feat:`, `fix:`, `docs:`, `chore:`).
- Deployment: **preview deploys on PR open via Vercel**; **production deploys only from `main`**; env vars managed in the **Vercel dashboard**.

### Product / architecture notes worth remembering
- Sprint 4 priorities: **task filtering** (`all / active / completed`).
- Stretch goal: **drag-and-drop reordering**.
- Tech debt item: **extract form into a separate component**.
- Architecture choices: App Router preferred for server component support; current state handled with `useState`; consider **Zustand** only if state complexity grows.

### Security / hygiene note
- `notes.md` contains staging credentials/endpoints. Do **not** repeat or store the secret values in long-term memory; treat them as sensitive and keep them out of summaries.

### Trust note
